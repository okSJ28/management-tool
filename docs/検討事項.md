## 1. 日次入力の未入力者へのチャット通知

### 背景

日次入力（始業前・終業前）が未入力の人に知らせる仕組みがない。今は、管理者が日次入力の「チームの入力状況」を見るか、本人が画面を開いたときにしか未入力に気づけない。

### 決めたこと（2026-11-09）

| 項目 | 内容 |
| --- | --- |
| 通知方法 | チャットツールに投稿（サーバーが投稿する）。**パターン① Teams**（試作済み）と **パターン② Rocket.Chat**（検討中）のどちらにするかは未定 |
| 通知先 | 本人＋管理者 |
| 対象 | 始業前（予定）・終業前（実績）の両方 |

### パターンの比較

| 項目 | ① Teams | ② Rocket.Chat |
| --- | --- | --- |
| 実現できるか | できる（試作済み） | できる（Rocket.Chat 標準の「着信 WebHook」で同じことができる。未試作） |
| 投稿の受け口 | チャネルのワークフロー「Webhook 要求を受信したらチャネルに投稿する」で発行した URL | 管理画面「統合（Integrations）」→「着信 WebHook」で発行した URL（`https://<サーバー>/hooks/<ID>/<トークン>`） |
| 受け口を作れる人 | チャネルのメンバーなら作れる（作った人のアカウントで投稿される） | Rocket.Chat の管理者（統合を管理する権限が必要）。投稿者として使うユーザー（通知用のボットユーザー推奨）を指定する |
| 本人への知らせ方 | チャネルの投稿でメンション（個人あてのチャットに送る仕組みは無い） | チャネルの投稿でメンション、または **本人に個別メッセージ（DM）** も送れる（投稿先を `@ユーザー名` に変えられる） |
| 管理者への知らせ方 | 同じチャネルの投稿を見る | 未入力者の一覧をチャネルに投稿（本人には DM、管理者用チャネルに一覧、と分けることもできる） |
| メンションに必要な情報 | 各ユーザーのメールアドレス（Teams のサインイン用） | 各ユーザーの **Rocket.Chat のユーザー名**（`@` の後ろの名前） |
| 投稿の見た目 | Adaptive Card（見出し・一覧・「日次入力を開く」ボタン） | テキスト（Markdown）＋添付（タイトル・リンク・色付きの帯）。ボタンの代わりにリンク |
| ネットワーク | 社外（`*.logic.azure.com`）。本番のコンテナからプロキシ経由で接続できることを確認済み | 社内サーバーなら社外に出ない。ただし本番のコンテナは全通信がプロキシ経由の設定（`HTTPS_PROXY`）のため、**社内のサーバー名を `NO_PROXY` に追加**するか、プロキシ経由で届くかの確認が必要 |
| 情報の置き場所 | 投稿内容（氏名・未入力の状況）が Microsoft 365 に載る | 社内サーバーなら社内にとどまる |
| ツール側の作り | 試作済み | ①の試作をほぼそのまま使える（判定・送る時刻・通知しない日・設定画面・送信履歴は共通）。投稿の形式とメンションの書き方、ユーザーの「チャットのユーザー名」欄、（使うなら）DM 送信を追加する。両方から選べる形にもできる |

### パターン①: Teams（試作済み）

#### 試作した内容（ブランチ `feature/teams-notify`、コミット `4d58169`）

- **送る時刻**: 平日の始業前の確認時刻（既定 10:00）と終業前の確認時刻（既定 17:00）。設定画面で変更可。サーバー停止などで時刻を過ぎても 1 時間以内なら送る。同じ日・同じ種類は 1 回だけ。全員入力済みなら投稿しない
- **未入力の判定**: 日次入力の「チームの入力状況」と同じ
  - 始業前: 予定なし、または予定（休暇を含む）の合計が 7.5h に足りない
  - 終業前: 実績なし（終日休暇の日は除く）
  - 特権管理者・除外した担当者は対象外
- **送らない日**: 土日と、新しいマスタ「通知：通知しない日」（2027 年までの祝日を初期登録。会社の休日は追加が必要）
- **投稿内容**: 見出し・時刻・未入力者の氏名と理由・「日次入力を開く」ボタン（Teams の Adaptive Card）。1 回の投稿に未入力者の一覧を載せ、メールアドレスを登録した人はメンションする
- **ユーザー管理**: 任意の「メールアドレス（Teams）」を追加（メンション用。管理者だけが見られる）
- **設定画面**（管理者のみ）: 有効／無効、Webhook URL、確認時刻、投稿に載せるツールの URL、テスト送信、今日の未入力者の確認と「今すぐ送信」、送信履歴
- **Webhook URL の扱い**: 知っていれば誰でもチャネルに投稿できるため、保存後は画面に出さず（ホスト名のみ表示）、JSON 出力・バックアップにも含めない
- 変更したファイル: `tool/core/notify.py`（新規）、`tool/api/features/notify.py`（新規）、`tool/core/auth.py`・`db.py`（`users.email` 列）、`tool/core/masters.json`（`notifySkipDates`）、`tool/server.py`（定期確認のスレッド）、`tool/web/js/api.js`・`views/settings.js`。README・仕様書・使い方ガイドの更新案もブランチに含む

#### 確認済みのこと

- 本番 DB のコピーで、Teams の代わりの受信サーバーを使い、API 32 項目・画面 12 項目すべて PASS（判定が日次入力と一致、メンション、自動送信が 1 回だけ、通知しない日は送らない、URL が漏れない、一般ユーザーは操作できない など）
- 本番サーバー（coverity01）のコンテナから、Teams のワークフローの Webhook が使うドメイン（`*.logic.azure.com`）にプロキシ経由で接続できる

#### 未確認・決めること（Teams）

1. **実際の Teams への投稿**: Webhook URL を発行してテスト送信で確認する（メンションが Teams のワークフロー経由で効くかも含めて）
2. **Webhook の発行**: どのチャネルに投稿するか、誰がワークフローを作るか（作成者のアカウントで投稿される）

### パターン②: Rocket.Chat（検討中・未試作）

#### しくみ

Rocket.Chat の **着信 WebHook（Incoming WebHook）** を使う。Rocket.Chat の管理者が「管理 → ワークスペース → 統合 → 新規 → 着信」で作成し、投稿先のチャネルと投稿者のユーザーを指定すると、URL（`https://<サーバー>/hooks/<ID>/<トークン>`）が発行される。ツールのサーバーがこの URL に JSON を POST すると、指定したチャネルに投稿される。

投稿の例（ツールから送る内容）:

```json
{
  "text": "日次入力（始業前）の入力のお願い 11/10（火）\n10:00 時点で、始業前の入力がまだの方がいます。\n- @kiuchi　予定が未入力\n- 柴村 拓弥　予定が未入力",
  "attachments": [
    { "title": "日次入力を開く", "title_link": "http://172.30.4.89:51400/#planInput", "color": "#2563eb" }
  ]
}
```

- `@ユーザー名` を本文に書くと、その人に通知が届く（チャネルのメンバーである必要がある）
- 本文に `"channel": "@kiuchi"` を加えると、そのチャネルではなく本人あての個別メッセージ（DM）として送れる。これを使うと「**本人には DM、管理者には未入力者一覧をチャネルに**」と分けられ、未入力者がチャネル上で目立たない形にもできる

#### ツール側でやること（①の試作からの差分）

- 設定画面に「送り先の種類（Teams ／ Rocket.Chat）」を追加し、送る形式を切り替える（判定・時刻・通知しない日・テスト送信・今すぐ送信・送信履歴は①をそのまま使う）
- ユーザー管理に「Rocket.Chat のユーザー名」欄を追加（①のメールアドレス欄と同じ扱い。管理者だけが見られる）
- 本人あての DM を使う場合は、「本人に DM で送る」「管理者用の一覧をチャネルに送る」の設定を追加する（未入力者が 10 名なら DM 10 件＋一覧 1 件）
- 本番のコンテナの `NO_PROXY` に Rocket.Chat のサーバー名を追加（社内サーバーで、プロキシ経由で届かない場合。`deploy/coverity01/docker-compose.yml` の `environment` に追記）

#### 未確認・決めること（Rocket.Chat）

1. **Rocket.Chat のサーバー**: 社内のどのサーバーか（URL）、バージョン。本番サーバー（coverity01）から接続できるか（プロキシの有無）
2. **着信 WebHook の作成**: Rocket.Chat の管理者に依頼できるか。投稿者に使うユーザー（ボット用のユーザー）を用意できるか
3. **ユーザー名の対応**: 各ユーザーの Rocket.Chat のユーザー名（社員番号と同じなど、決まりがあれば自動で対応付けられる）
4. **本人への知らせ方**: チャネルでメンションするか、本人に DM するか（DM の場合、`channel` の指定で DM が送れるかを実機で確認する）
5. **試作の要否**: ②に決めるなら、①の試作をもとに Rocket.Chat 用に作り替えて、受信サーバーと実機で確認する

### 共通の未確認・決めること
