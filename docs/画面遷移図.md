## 1. 凡例

| 表記 | 意味 |
| --- | --- |
| 角丸の四角 | 画面（ビュー）。サイドバーのナビゲーションに現れる単位 |
| 平行四辺形 | ドロワー（右からスライドするパネル）。画面遷移せず、上に重なる |

- 現在の画面は URL ハッシュ（例: `#tasks`）に反映され、ブラウザの戻る／進むに対応する

## 3. 全体構成

サイドバー上部のタブで 2 つのアプリを切り替える。`settings` のみ両アプリから参照される共通画面。

```mermaid
flowchart TB
    START(["起動 （ブラウザで URL を開く）"]) --> AUTH{"ログイン済み？"}
    AUTH -- "いいえ" --> LOGIN[/"ログイン画面"/]
    LOGIN -- "ID・パスワード" --> BOOT
    AUTH -- "はい" --> BOOT{"データあり？"}
    BOOT -- "あり" --> DASH["ダッシュボード<br/>#dashboard"]
    BOOT -- "なし" --> IO["取込 / 出力<br/>#io"]

    DASH --> TAB
    IO --> TAB
    TAB{{"サイドバー上部のアプリ切替タブ"}}
    TAB -- "🧩 開発管理" --> DEVAPP["開発プログラム管理<br/>8画面"]
    TAB -- "📝 業務予定" --> PLANAPP["業務予定管理<br/>4画面"]

    DEVAPP --- SET["設定 #settings<br/>（両アプリ共通・管理者のみ）"]
    PLANAPP --- SET
```

![全体構成](images/fig-01-overview.png)

- アプリを切り替えると、そのアプリの先頭画面（`dashboard` / `planAssign`）へ遷移する
- 他アプリの画面 ID を直接指定した場合（ハッシュ入力・画面内リンク）は、アプリも自動的に切り替わる
- `settings` は例外で、どちらのアプリからでもアプリを切り替えずに表示される
- `settings` は管理者のみ表示される。一般ユーザーにはナビ項目が出ず（業務予定管理の「管理」グループごと非表示）、
  ハッシュで直接指定しても「この画面は管理者のみ利用できます」と通知して遷移しない

## 6. 共通 UI からの遷移

画面を問わず、上部バーとキーボードから利用できる遷移。

```mermaid
flowchart LR
    ANY["任意の画面"]
    USER[/"アカウントドロワー<br/>（パスワード変更・ログアウト）"/]
    LOGIN[/"ログイン画面"/]
    QADD1[/"タスク編集ドロワー"/]
    QADD2[/"日次記録エディタ"/]
    SEARCH["同一画面で絞り込み再描画"]

    ANY -.->|"👤 アカウントバッジ"| USER
    USER -->|"ログアウト（再読込）"| LOGIN
    ANY -.->|"セッション期限切れ（API が 401）"| LOGIN
    LOGIN -.->|"同じ ID で再ログイン<br/>（編集中の画面を維持）"| ANY
    ANY -->|"🔍 横断検索 / Ctrl+K"| SEARCH
    ANY -.->|"「＋ 新規登録」/ Ctrl+N<br/>【開発管理のとき】"| QADD1
    ANY -.->|"「＋ 新規登録」/ Ctrl+N<br/>【業務予定のとき】"| QADD2
    USER -.->|"Esc / 閉じる"| ANY
    QADD1 -.->|"Esc / 保存"| ANY
    QADD2 -.->|"Esc / 保存"| ANY
```

![共通 UI からの遷移](images/fig-06-common-ui.png)

| 操作 | 効果 |
| --- | --- |
| `Ctrl + K` | 横断検索へフォーカス。入力すると現在の画面が絞り込まれて再描画される |
| `Ctrl + N` | 表示中のアプリに応じた新規登録ドロワーを開く |
| `Esc` | ドロワー／モーダルを閉じる |
| ブラウザの戻る／進む | URL ハッシュの変更を検知して該当画面へ遷移 |

## 7. 起動時フロー

```mermaid
sequenceDiagram
    participant U as 利用者
    participant B as ブラウザ
    participant S as サーバー

    U->>B: 起動バット実行 / URL を開く
    B->>S: GET /  （HTML・CSS・JS）
    S-->>B: 静的ファイル
    B->>B: 互換性チェック（fetch / Promise 等）
    B->>S: GET /api/bootstrap（Cookie dpm_session）
    opt 未ログイン・期限切れ（401）
        S-->>B: 401 unauthorized
        B-->>U: ログイン画面
        U->>B: ID・パスワード
        B->>S: POST /api/auth/login
        S-->>B: Set-Cookie: dpm_session
        B->>S: GET /api/bootstrap（再試行）
    end
    S-->>B: schema・masters・tasks・plans・entries・account
    alt 取得成功
        B->>B: 前回のアプリ・画面を復元<br/>（localStorage / URLハッシュ、権限の無い画面は除く）
        B-->>U: 画面表示
        loop 20秒ごと
            B->>S: GET /api/version
            S-->>B: updatedAt
            B->>B: 変化があれば再取得して再描画
        end
    else 取得失敗・タイムアウト（30秒）
        B-->>U: エラーカード＋「再読み込み」ボタン
    end
```

![起動時フロー](images/fig-07-boot-sequence.png)

- データが 1 件も無い場合は、起動直後に `io`（取込 / 出力）へ自動遷移する
- ドロワー表示中・ログイン画面表示中は自動同期による再描画を抑止する（入力内容の消失防止）
- 別の ID でログインし直した場合は、画面と権限を切り替えるためページを再読込する

## 9. 画面遷移に関する補足仕様

| 項目 | 内容 |
| --- | --- |
| 画面の記憶 | 選択中のアプリは `localStorage`（`dpm.app`）、画面は URL ハッシュに保持する |
| 絞り込み条件の保持 | `tasks` のフィルタ・表示列は `localStorage`（`dpm.tasks`）に保存し、再訪時に復元する |
| 画面内状態 | ガントの期間、分析の軸・指標、予定ボードの表示日数などはセッション中のみ保持（再読込で初期値に戻る） |
| 遷移時の引き継ぎ | `App.go(画面ID, パラメータ)` の第 2 引数で担当者・案件などの絞り込み条件を渡す |
| エラー時 | 描画中に例外が発生しても画面全体は落とさず、当該ビュー領域にエラーメッセージを表示する |
| 排他 | 画面遷移による排他制御は行わない。他利用者の更新は 20 秒ごとのポーリングで反映される |
| 権限 | 画面定義の `adminOnly` が真の画面（`settings`）は管理者以外に表示しない。サーバー側でも該当 API を 403 で拒否する |
| ログイン ID の記憶 | 最後にログインした ID を `localStorage`（`dpm.loginId`）に保存し、ログイン画面に補完する |
