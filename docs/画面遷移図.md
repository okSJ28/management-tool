## 3. 全体構成

サイドバー上部のタブで 2 つのアプリを切り替える。`settings` のみ両アプリから参照される共通画面。

```mermaid
flowchart TB
    START(["起動 （ブラウザで URL を開く）"]) --> AUTH{"ログイン済み？"}
    AUTH -- "いいえ" --> LOGIN[/"ログイン画面"/]
    LOGIN -- "ID・パスワード" --> BOOT
    AUTH -- "はい" --> BOOT{"データあり？"}
    BOOT -- "あり" --> DASH["ダッシュボード<br/>#dashboard"]
    BOOT -- "なし" --> IO["取込 / 出力<br/>#io"]

    DASH --> TAB
    IO --> TAB
    TAB{{"サイドバー上部のアプリ切替タブ"}}
    TAB -- "🧩 開発管理" --> DEVAPP["開発プログラム管理<br/>8画面"]
    TAB -- "📝 業務予定" --> PLANAPP["業務予定管理<br/>4画面"]

    DEVAPP --- SET["設定 #settings<br/>（両アプリ共通・管理者のみ）"]
    PLANAPP --- SET
```

![全体構成](images/fig-01-overview.png)

- アプリを切り替えると、そのアプリの先頭画面（`dashboard` / `planAssign`）へ遷移する
- 他アプリの画面 ID を直接指定した場合（ハッシュ入力・画面内リンク）は、アプリも自動的に切り替わる
- `settings` は例外で、どちらのアプリからでもアプリを切り替えずに表示される
- `settings` は管理者のみ表示される。一般ユーザーにはナビ項目が出ず（業務予定管理の「管理」グループごと非表示）、
  ハッシュで直接指定しても「この画面は管理者のみ利用できます」と通知して遷移しない

### 5.1 日次入力の画面内フロー

`planInput` は 1 作業＝1 行の予実一体シートで、同じ行の左に予定、右に実績を入力する。
「始業前」「終業前」は同じシートの左右の列で扱い、画面遷移は発生しない。

```mermaid
flowchart TB
    A["日次入力を開く"] --> B["対象日を選択<br/>（担当者の切替は管理者のみ）"]
    B --> C{"入力タイミング"}
    C -->|"☀ 始業前"| D["「＋ 作業を追加（予定）」<br/>工程・案件・作業内容・予定h"]
    C -->|"🌙 終業前"| E["同じ行の右側に入力<br/>進捗率・実績h（空欄は予定h）・状況"]
    C -->|"🌙 予定外"| F["「＋ 予定外の作業を追加」<br/>実績のみの行"]
    D --> G{"必須チェック<br/>工程・（実績ありなら）進捗率"}
    E --> G
    F --> G
    G -- "NG" --> I["エラー表示（保存しない）"]
    G -- "OK" --> H{"予定の合計が<br/>基準 7.5h 以上か"}
    H -- "不足" --> M{{"確認モーダル<br/>「このまま保存」"}}
    M -- "キャンセル" --> B
    M -- "このまま保存" --> J
    H -- "OK" --> J["💾 保存 / Ctrl+S<br/>予定・実績をまとめて保存"]
    J --> K["シート・前回の入力・<br/>チーム入力状況（管理者のみ）を再描画"]
    B -. "未保存の変更あり" .-> L{"切替を確認"}
    L -- "キャンセル" --> B
```

> 図版（PNG）は旧レイアウト時点のもの。最新は上記 mermaid を参照。

![日次入力の画面内フロー](images/fig-05-plan-input-flow.png)

シートの下には、参照用の **前回の入力**（直近 7 日以内で入力がある日の内容・編集不可）と、
管理者のみ **チームの入力状況** を表示する。いずれも同じ画面内の折りたたみ領域で、画面遷移は発生しない。

### 5.2 権限による動作の違い

業務予定（予定・実績・取組み予定）は、一般ユーザーは自分の担当者の記録のみ登録・変更・削除できる。管理者（特権管理者を含む）は全員分を扱える。

| 画面・操作 | 一般ユーザー | 管理者 |
| --- | --- | --- |
| 日次入力 の担当者選択 | 自分に固定（変更不可） | 全担当者から選択 |
| 日次入力 のチーム入力状況 | 表示しない | 表示。行クリックでその担当者に切替 |
| 日次入力 の前回の入力 | 自分の分を表示（参照のみ） | 選択中の担当者の分を表示（参照のみ） |
| チーム予定ボード の空セルクリック | 自分の行のみ日次記録エディタを開く（予定・実績どちらの列かで種別を初期設定） | 全員の行で開く |
| 定例予定の登録 の担当者 | 自分に固定 | 複数選択可（既定はログイン中の担当者） |
| 「この日以降の定例を削除」 | 自分の分のみ削除 | 同じ定例の全担当者分を削除 |
| 他の担当者の記録・取組み予定を開く | 閲覧専用ドロワー（「記録を表示」「取組み予定を表示」。保存・削除なし） | 通常のエディタ |
| 各エディタの担当者欄 | 自分に固定 | 全担当者から選択 |
| 各エディタの「開発タスクと紐付け」の候補 | 自分が担当のタスクのみ | エディタで選んだ担当者のタスクのみ（担当者を変えると入れ替わる） |
| 上部バーの横断検索 | 表示しない | 検索に対応した画面（一覧・入力、ガント、取組み予定、チーム予定ボード）でのみ表示 |
| 一覧・入力 の一括削除ボタン | 表示しない（一括の状態変更は可） | 表示 |
| 取込 / 出力 の取込方法「全件置換」 | 表示しない（更新＋追加・すべて追加のみ） | 表示 |

## 6. 共通 UI からの遷移

画面を問わず、上部バーとキーボードから利用できる遷移。

```mermaid
flowchart LR
    ANY["任意の画面"]
    USER[/"アカウントドロワー<br/>（パスワード変更・ログアウト）"/]
    LOGIN[/"ログイン画面"/]
    SEARCH["同一画面で絞り込み再描画"]

    ANY -.->|"👤 アカウントバッジ"| USER
    USER -->|"ログアウト（再読込）"| LOGIN
    ANY -.->|"セッション期限切れ（API が 401）"| LOGIN
    LOGIN -.->|"同じ ID で再ログイン<br/>（編集中の画面を維持）"| ANY
    ANY -->|"🔍 横断検索 / Ctrl+K<br/>【管理者・検索対応画面のみ】"| SEARCH
    USER -.->|"Esc / 閉じる"| ANY
```

![共通 UI からの遷移](images/fig-06-common-ui.png)

| 操作 | 効果 |
| --- | --- |
| `Ctrl + K` | 横断検索へフォーカス。入力すると現在の画面が絞り込まれて再描画される。横断検索は管理者のみ、検索に対応した画面（`tasks`・`gantt`・`planAssign`・`planBoard`）でのみ表示し、それ以外の画面へ移ると検索条件を解除する |
| `Esc` | ドロワー／モーダルを閉じる |
| ブラウザの戻る／進む | URL ハッシュの変更を検知して該当画面へ遷移 |

## 7. 起動時フロー

```mermaid
sequenceDiagram
    participant U as 利用者
    participant B as ブラウザ
    participant S as サーバー

    U->>B: 起動バット実行 / URL を開く
    B->>S: GET /  （HTML・CSS・JS）
    S-->>B: 静的ファイル
    B->>B: 互換性チェック（fetch / Promise 等）
    B->>S: GET /api/bootstrap（Cookie dpm_session）
    opt 未ログイン・期限切れ（401）
        S-->>B: 401 unauthorized
        B-->>U: ログイン画面
        U->>B: ID・パスワード
        B->>S: POST /api/auth/login
        S-->>B: Set-Cookie: dpm_session
        B->>S: GET /api/bootstrap（再試行）
    end
    S-->>B: schema・masters・tasks・plans・entries・account
    alt 取得成功
        B->>B: 前回のアプリ・画面を復元<br/>（localStorage / URLハッシュ、権限の無い画面は除く）
        B-->>U: 画面表示
        loop 20秒ごと
            B->>S: GET /api/version
            S-->>B: updatedAt
            B->>B: 変化があれば再取得して再描画
        end
    else 取得失敗・タイムアウト（30秒）
        B-->>U: エラーカード＋「再読み込み」ボタン
    end
```

![起動時フロー](images/fig-07-boot-sequence.png)

- データが 1 件も無い場合は、起動直後に `io`（取込 / 出力）へ自動遷移する
- ドロワー表示中・ログイン画面表示中は自動同期による再描画を抑止する（入力内容の消失防止）
- 別の ID でログインし直した場合は、画面と権限を切り替えるためページを再読込する

## 9. 画面遷移に関する補足仕様

| 項目 | 内容 |
| --- | --- |
| 画面の記憶 | 選択中のアプリは `localStorage`（`dpm.app`）、画面は URL ハッシュに保持する |
| 絞り込み条件の保持 | `tasks` のフィルタ・表示列は `localStorage`（`dpm.tasks`）に保存し、再訪時に復元する |
| 画面内状態 | ガントの期間、分析の軸・指標、予定ボードの表示日数などはセッション中のみ保持（再読込で初期値に戻る） |
| 遷移時の引き継ぎ | `App.go(画面ID, パラメータ)` の第 2 引数で担当者・案件などの絞り込み条件を渡す |
| エラー時 | 描画中に例外が発生しても画面全体は落とさず、当該ビュー領域にエラーメッセージを表示する |
| 排他 | 画面遷移による排他制御は行わない。他利用者の更新は 20 秒ごとのポーリングで反映される（未保存の変更がある画面の表示中は再描画しない） |
| 権限 | 画面定義の `adminOnly` が真の画面（`settings`）は管理者以外に表示しない。サーバー側でも該当 API を 403 で拒否する。業務予定は画面遷移を制限せず、編集可否のみ担当者で判定する（5.2） |
| ログイン ID の記憶 | 最後にログインした ID を `localStorage`（`dpm.loginId`）に保存し、ログイン画面に補完する |
